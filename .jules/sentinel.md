## 2024-05-24 - Fix path traversal in FileDownloader
**Vulnerability:** The FileDownloader.java `downloadFile` method constructed a file path using `new File(mCacheDir, new File(url).getName())`. A maliciously crafted url like `http://evil.com/..%2f..%2fetc%2fpasswd` would result in the filename `..%2f..%2fetc%2fpasswd` being downloaded to `mCacheDir` allowing path traversal to overwrite files outside of the `mCacheDir`.
**Learning:** `new File(url).getName()` only handles backslash and slash separators literally, not URL-encoded paths. A URL with encoded traversals like `%2f` is treated as a single filename by `new File` constructors. When written, the operating system translates these to file separators if the path is requested as a canonical or absolute path, leading to arbitrary file overwrite within app data bounds.
**Prevention:** Always validate canonical paths against the canonical path of the intended base directory (plus `File.separator`) when constructing file paths from any external input.
