## 2024-05-19 - [CacheableWebView LFI via setAllowFileAccess]
**Vulnerability:** A Local File Inclusion (LFI) vulnerability existed because `CacheableWebView` explicitly enabled `setAllowFileAccess(true)`. When combined with a vulnerable `WebViewClient`, this allowed untrusted web content to read arbitrary files from the local filesystem.
**Learning:** WebView security is a combination of generic settings (like `setAllowFileAccess`) and custom URL routing implementations (like `shouldInterceptRequest`). When turning off broad settings for security, we must specifically and safely implement the offline behavior (e.g. `file://.../cache/...mht`) without falling back into naive string replacements or exposing `..` path traversal vulnerabilities. Moreover, any shared state mapped in `shouldInterceptRequest` needs `ConcurrentHashMap` as the callbacks are run on background threads.
**Prevention:** Always default `setAllowFileAccess(false)`. Safely proxy authorized local cache access in the WebViewClient using `WebResourceResponse` while utilizing explicit `getCanonicalPath()` bound checks to prevent path traversal. Avoid `HashMap` inside WebViewClient lifecycle intercepts.
