## 2025-03-27 - Path Traversal Prevention in File Objects
**Vulnerability:** Path traversal in Java `File` objects constructed with dynamic filenames.
**Learning:** `new File(url).getName()` successfully extracts the final segment after the last `/`, protecting against `../` path traversal. However, it does NOT decode URL-encoded slashes (`%2f`). If the extracted filename string containing `%2f` is used to construct a `File`, it does NOT cause a path traversal on Android/Linux filesystems because the filesystem treats `%2f` as a literal string. Yet, to enforce strict directory constraints against *any* possible bypass, constructing a canonical path and validating it against the intended directory's canonical path is necessary.
**Prevention:** Do not attempt to use `Uri.parse(url).getPath()` to replace `new File(url).getName()` to extract filenames from raw URLs, as it breaks root URL downloads by returning empty strings. Instead, directly validate the resulting `File` object using `getCanonicalPath().startsWith(baseDirCanonicalPath + File.separator)`.
