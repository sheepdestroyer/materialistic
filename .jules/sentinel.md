## 2025-02-27 - WebView Local File Inclusion (LFI) via setAllowFileAccess
**Vulnerability:** `setAllowFileAccess(true)` was globally enabled in a custom WebView (`CacheableWebView`), allowing potentially malicious web content to read arbitrary local files on the device using `file://` URLs.
**Learning:** Android WebViews have historically struggled with safe local file access. Setting `setAllowFileAccess(false)` is crucial for mitigating LFI, but it breaks offline caching features that rely on serving local files.
**Prevention:** Always default to `setAllowFileAccess(false)`. If local files must be served (e.g., for offline archives), implement a strict manual interception in `WebViewClient.shouldInterceptRequest`. Ensure this interception natively passes through Android's safe asset schemes (`file:///android_asset/` and `file:///android_res/`), strictly validates canonical paths against the app's cache/data directories to prevent path traversal (`../`), and correctly infers MIME types to prevent rendering breakages. Additionally, ensure thread-safety (e.g., using `ConcurrentHashMap`) for any shared state within `shouldInterceptRequest`, as it is invoked on background threads.
