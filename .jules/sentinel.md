## 2024-05-24 - Fix Local File Inclusion (LFI) via WebView interception
**Vulnerability:** AdBlockWebViewClient did not validate intercepted file:// URLs, allowing an attacker to bypass cache constraints and access arbitrary local files via LFI when shouldInterceptRequest intercepted URLs.
**Learning:** Using new File(url) or naive string replace fails on URL encoded paths and lacks base directory validation. Native WebView file loading handles these securely but custom interception overrides the native behavior and therefore must manually reimplement the constraints, especially when webSettings.setAllowFileAccess(true) is required for normal operation. Additionally, WebViewClient methods run on background threads and shared states need thread safe collections like ConcurrentHashMap.
**Prevention:** Always decode the path before creating a File object. Use getCanonicalPath() on the file and ensure it starts with the canonical path of the intended directory (e.g. getCacheDir().getCanonicalPath() + File.separator). If it fails validation, return an empty WebResourceResponse to block the request. If it passes, return null to let the native secure loader handle it.
