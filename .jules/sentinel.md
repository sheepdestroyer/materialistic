## 2025-02-27 - LFI Vulnerability in CacheableWebView
**Vulnerability:** `CacheableWebView` explicitly called `setAllowFileAccess(true)`, enabling local file inclusion (LFI) via the `file://` scheme in WebViews handling potentially untrusted URLs.
**Learning:** `setAllowFileAccess(true)` is dangerous as it allows javascript inside the webview to read arbitrary local files from the app's internal storage or SD card. By default, `file:///android_asset/` and `file:///android_res/` are allowed even when it's `false`, so setting it to `false` does not break asset rendering. The app uses `.mht` file caches loaded by `AdBlockWebViewClient`. Instead of intercepting all `file://` URLs, which can break asset loading if poorly written, we should only intercept accesses strictly for allowed cached files and return `null` for everything else so standard asset loading works correctly.
**Prevention:** Always leave `setAllowFileAccess` to its secure default (`false`). Implement targeted `WebResourceResponse` interceptors only for specific authorized offline files, returning `null` (not an empty string/response) for unauthorized `file://` URLs so native handler takes over.
