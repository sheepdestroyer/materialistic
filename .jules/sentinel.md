## 2024-05-24 - Path Traversal Vulnerability in file:// Protocol
**Vulnerability:** The AdBlockWebViewClient intercepted `file://` URLs for loading cached items, but it failed to perform directory traversal checks on the parsed file path. This would allow an attacker to read arbitrary files via `file:///...` if they could induce the application to load the URL, as the original logic only blocked files not in the map when checking for ads.
**Learning:** `WebViewClient.shouldInterceptRequest` is the primary mechanism to enforce application-layer URL access controls. When supporting caching via `file://`, robust checks including `File.getCanonicalPath()` and `startsWith(expectedDir)` with `File.separator` are strictly required to prevent directory traversal (`../`).
**Prevention:** Always use `getCanonicalPath()` when dealing with user-controlled or intercepted `file://` URIs and compare against an expected absolute root path (plus file separator) before providing the resource. Ensure any external resource loading explicitly blocks `file://` loading for everything outside expected bounds via fallback responses like `new WebResourceResponse("text/plain", "utf-8", new ByteArrayInputStream("".getBytes()))`.
