## 2024-05-18 - [WebView LFI Bypass via URL Encoding]
**Vulnerability:** A Local File Inclusion (LFI) vulnerability check in a `WebViewClient` was bypassed. The code validated the raw, URL-encoded string (`url.replace("file://", "")`) instead of decoding it first.
**Learning:** Java's `File` class does not automatically URL-decode input. When validating paths against malicious traversal payloads (e.g. `%2e%2e%2f` instead of `../`), passing the encoded string to `new File()` treats `%2e%2e` as a literal directory name, bypassing the validation logic. However, the downstream system (Chromium WebView) *does* decode the URL, resulting in a successful path traversal. Furthermore, URL schemes are case-insensitive, so `startsWith("file://")` is easily bypassed with `FiLe://`.
**Prevention:** Always use `Uri.parse(url).getPath()` to extract the properly decoded path before creating a `File` object for canonical path validation. Always perform case-insensitive scheme checks (`url.toLowerCase().startsWith(...)`).
